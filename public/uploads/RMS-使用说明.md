## 1. 快速上手

### 1.1 三分钟入门

| 步骤 | 操作 | 耗时 |
|------|------|------|
| ① | 浏览器打开 `http://localhost:3800` | 5s |
| ② | 用管理员账号 `admin` 登录 | 10s |
| ③ | 点击「仪表盘」查看系统总览 | 10s |
| ④ | 点击「需求列表」→「+ 新建需求」 | 30s |
| ⑤ | 在「看板」拖动需求卡片变更状态 | 20s |

### 1.2 推荐学习路径

```
新用户  →  第 2 章（登录）→  第 3.1~3.3（创建/查看需求）→  第 3.6（评论附件）
业务方  →  第 3.1（创建需求）→  第 3.5（看板）→  第 6 章（AI 聊天）
开发    →  第 3.1~3.4（需求全流程）→  第 4 章（多视图）→  第 5 章（知识库）
管理员  →  全部章节（按需查阅）
```

## 2. 登录与账户

### 2.1 登录页面

![登录页](./images/ui-login.png)

**步骤：**

1. 打开 `http://localhost:3800`
2. 输入用户名（如 `admin`）
3. 输入密码（首次密码请见部署文档或联系管理员）
4. 点击「登录」

### 2.2 四种登录方式

| 方式 | 适用场景 | 入口 |
|------|----------|------|
| **用户名+密码** | 默认，所有人 | 登录页主表单 |
| **企微扫码** | 企业内用户 | 登录页「💬 微信」按钮 |
| **飞书登录** | 飞书生态 | 登录页「📨 飞书」按钮 |
| **钉钉登录** | 钉钉生态 | 登录页「💼 钉钉」按钮 |

> 💡 第三方登录首次使用会自动创建账号并分配默认角色（可在系统配置修改）。

### 2.3 退出登录

点击左下角用户头像旁的「退出」按钮，或访问 `/api/auth/logout`。

### 2.4 忘记密码

联系全局管理员（global_admin）重置。流程：

```
管理员 → 用户管理 → 找到用户 → 编辑 → 重置密码
```

## 3. 需求管理

### 3.1 需求列表

![需求列表](./images/ui-requirement-list.png)

#### 3.1.1 筛选与搜索

- **顶部搜索框**：按标题、描述、编号全文搜索
- **状态下拉**：单选或全选
- **优先级下拉**：高 / 中 / 低 / 全部
- **项目下拉**：按可见项目过滤
- **导出按钮**：把当前筛选结果导出为 CSV / Excel

#### 3.1.2 列表字段

| 列 | 含义 |
|----|------|
| 编号 | #128（点击进入详情） |
| 标题 | 需求简述 |
| 📎 N | 附件数 |
| 💬 N | 评论数 |
| 状态 | 7 种状态徽章（颜色编码） |
| 优先级 | 高（红）/ 中（黄）/ 低（蓝） |
| 项目 | 所属项目 |
| 处理人 | 当前处理人头像 |
| 更新时间 | 相对时间（2 小时前） |

#### 3.1.3 分页与排序

- 默认每页 30 条，可在右上角下拉切换
- 点击列头排序（编号、更新时间）
- 底部翻页

### 3.2 创建需求

**步骤：**

1. 在需求列表点击「+ 新建需求」按钮
2. 填写表单：
   - **标题**（必填，简明扼要，≤ 500 字）
   - **描述**（必填，详细说明背景、目标、验收标准）
   - **项目**（必选）
   - **优先级**（高/中/低）
   - **分类**（项目需求 / 零星需求）
   - **处理人**（可选，未指定时由管理员分派）
   - **截止日期**（可选）
   - **附件**（可选，支持拖拽多文件）
3. 点击「保存」

**小技巧：**
- 使用 Markdown 语法书写描述
- 引用其他需求：输入 `#` 选择
- 上传图片直接拖到描述框
- 紧急需求勾选「高优先级」会触发即时通知

### 3.3 需求详情

**详情页布局：**

```
┌──────────────────────────────────────────────┐
│ 标题: #128 手机号验证码登录            [⋯]  │
│ 状态: 已排期  优先级: 中  项目: 电商平台     │
├──────────────────────────────────────────────┤
│ Tab: 描述 | 评论(5) | 附件(2) | 历史 | 关系  │
├──────────────────────────────────────────────┤
│ [描述内容]                                     │
│ 用户希望使用手机号+验证码登录                  │
│ - 验证码 6 位，60s 过期                        │
│ - 需要图形验证码防刷                            │
│ ...                                            │
├──────────────────────────────────────────────┤
│ 操作: [▶ 开始处理] [✓ 提交完成] [✕ 关闭]      │
└──────────────────────────────────────────────┘
```

#### 3.3.1 五个 Tab

| Tab | 内容 |
|-----|------|
| **描述** | 主描述、验收标准、技术备注 |
| **评论** | 时间线式的讨论区，支持 @人 |
| **附件** | 文件列表，支持预览、下载、新增 |
| **历史** | 状态变更日志（谁、何时、从什么到什么） |
| **关系** | 关联需求、父子需求、重复需求 |

#### 3.3.2 状态操作按钮

根据当前状态动态显示可用操作：

| 当前状态 | 可执行操作 |
|----------|-----------|
| 待评估 | 评估通过 / 关闭 |
| 已排期 | 开始处理 / 退回重新评估 |
| 处理中 | 提交完成 / 暂停 / 退回 |
| 已完成 | 验证通过 / 退回处理 |
| 已验证 | 关闭 |

### 3.4 状态流转（拖拽）

在「看板」视图直接拖动卡片到目标列即可改变状态。系统会自动：

- 写入 `status_log`
- 通知新处理人
- 触发 SLA 计时更新

![看板](./images/ui-kanban.png)

### 3.5 评论

**三种评论方式：**

1. **顶部输入框**：在详情页评论 Tab 直接输入
2. **@提及**：输入 `@` 选择用户，被 @ 的人会收到通知
3. **引用回复**：鼠标悬停评论会出现「回复」按钮

**Markdown 支持：**
- `**加粗**`、`*斜体*`、`` `代码` ``
- 链接自动识别
- 表情 `:smile:` → 😄
- 代码块 ` ``` `

### 3.6 附件

**支持格式：**
- 图片：jpg、png、gif、webp、svg
- 文档：pdf、docx、xlsx、pptx
- 压缩包：zip、tar.gz（≤ 100MB）
- 音视频：mp4、mp3（可选配 ASR 自动转写文字）

**操作：**
- 拖拽到附件区域即可上传
- 点击附件名预览 / 下载
- 鼠标悬停出现「删除」按钮（仅上传者或管理员）

### 3.7 标签

**添加标签：**
1. 在需求详情「标签」区域点击「+ 添加标签」
2. 输入新标签名或从下拉选择
3. 支持批量打标（在列表勾选多个需求 → 批量操作 → 添加标签）

**管理标签：** 管理员 → 系统配置 → 标签管理

## 4. 多视图协作

### 4.1 视图总览

| 视图 | 路径 | 适用场景 |
|------|------|----------|
| **列表** | `/requirements` | 全局浏览、筛选、批量操作 |
| **看板** | `/kanban` | 拖拽改状态、可视化瓶颈 |
| **甘特** | `/gantt` | 时间线、依赖、里程碑 |
| **日历** | `/calendar` | 按日期查看计划/截止 |
| **仪表盘** | `/dashboard` | 整体指标和趋势 |
| **工作量** | `/workload` | 团队产能分析 |

### 4.2 看板

**特性：**
- 7 列对应 7 个状态
- 拖拽卡片改变状态
- 卡片显示：编号、标题、优先级、处理人头像、附件/评论数
- 列头显示卡片数量
- 支持按项目/处理人筛选

### 4.3 甘特图

**特性：**
- 时间轴按周/月/季切换
- 任务条按开始/结束时间绘制
- 显示依赖关系（箭头）
- 里程碑用菱形标记
- 鼠标悬停显示详情
- 拖拽调整时间

### 4.4 日历

**特性：**
- 月视图 / 周视图 / 日视图
- 显示计划开始日、截止日
- 不同优先级不同颜色
- 点击日期快速创建需求

### 4.5 仪表盘

**4 个 KPI 卡片：**
- 总需求数
- 待处理数
- 本月完成数
- 平均处理时长

**2 个图表：**
- 6 月趋势折线图
- 状态分布饼图

**最近需求列表：** 显示最近 10 条更新

### 4.6 工作量

**维度切换：**
- 按人 → 每人处理数、完成率、平均时长
- 按项目 → 各项目需求分布、进度
- 按时间 → 每日/周/月 提交数

**导出：** 支持 Excel

## 5. 知识库

### 5.1 知识库入口

`/knowledge` 路径，列出所有知识条目。

### 5.2 知识条目来源

| 来源 | 说明 |
|------|------|
| **手动创建** | 知识库 → 新建知识 |
| **从需求沉淀** | 需求详情 → 操作 → 沉淀为知识 |
| **AI 自动生成** | AI 聊天 → 「生成知识」 |
| **批量导入** | 管理后台 → 知识库 → 导入 |

### 5.3 知识图谱

`/knowledge/graph` 显示知识条目之间的关联：

- 节点 = 知识条目
- 边 = 关联类型（相关 / 引用）
- 鼠标悬停查看摘要
- 点击节点打开详情

### 5.4 反馈机制

每个知识条目有「👍 有用 / 👎 没用」按钮，反馈会用于：

- AI 训练排序
- 推荐相似知识
- 识别低质量条目

## 6. AI 聊天与 MCP 集成

### 6.1 AI 聊天（Web UI）

`/chat` 路径，使用 LLM 进行对话。

**能力：**
- 回答系统使用问题
- 摘要复杂需求
- 智能搜索
- 生成知识草稿
- 数据分析（如「上个月完成了多少需求？」）

**支持配置 LLM：**
- 管理员 → 系统配置 → LLM
- 填写 API URL、Key、模型名
- 多个 LLM 厂商：OpenAI、Stepfun、Anthropic 等

### 6.2 MCP 集成

#### 6.2.1 什么是 MCP

MCP（Model Context Protocol）是 Anthropic 提出的 AI 工具调用标准。RMS 提供官方 MCP Server，AI 客户端（如 Claude Desktop、Cursor）可直接调用。

#### 6.2.2 安装步骤

**步骤 1：创建 Access Token**

1. 登录 RMS
2. 点击左下角用户头像 → 「🔑 Token 管理」
3. 点击「+ 创建新 Token」
4. 输入名称（如 `Claude Desktop`）
5. **复制 Token**（仅显示一次！）

![Token 管理](./images/ui-tokens.png)

**步骤 2：配置 MCP 客户端**

在 Claude Desktop 的 `claude_desktop_config.json` 中：

```json
{
  "mcpServers": {
    "rms": {
      "command": "node",
      "args": ["/path/to/rms/rms-mcp-server.js"],
      "env": {
        "RMS_URL": "http://localhost:3800",
        "RMS_TOKEN": "rms_xxxxxxxxxxxx"
      }
    }
  }
}
```

**步骤 3：重启 Claude Desktop**

现在可以在对话中让 Claude 直接操作 RMS：

```
你: 列出我所有待处理的需求
Claude: [调用 list_requirements 工具] 你有 5 个待处理需求...
你: 帮我把 #128 的状态改成"处理中"
Claude: [调用 transition_requirement 工具] 已成功将 #128 改为处理中
```

#### 6.2.3 常用 MCP 工具

| 工具 | 示例 |
|------|------|
| `list_requirements` | "列出本周新增的需求" |
| `get_requirement` | "查看 #128 的详情" |
| `create_requirement` | "创建一个新需求：修复登录页样式" |
| `transition_requirement` | "把 #128 标记为已完成" |
| `add_comment` | "在 #128 加个评论：已修复" |
| `get_dashboard` | "看看这周完成情况" |
| `search` | "搜索所有提到'性能'的需求" |

#### 6.2.4 HTTP 兜底（CLI）

如果 MCP 不可用，可直接用 HTTP API：

```bash
# 列出待处理需求
node rms-api.js list --status in_progress --token rms_xxx

# 获取需求详情
node rms-api.js get 128 --token rms_xxx

# 创建需求
node rms-api.js create \
  --title "新需求" \
  --description "..." \
  --project 1 \
  --priority high \
  --token rms_xxx
```

### 6.3 OpenClaw 集成

OpenClaw 是本地 AI Agent 网关（端口 18789），可编排多个 MCP 工具。

**步骤：**
1. 启动 OpenClaw Gateway
2. 在 OpenClaw 配置中注册 RMS MCP Server
3. 通过 OpenClaw 直接对话控制 RMS

详细配置见 `/admin/integrations` 页面。

## 9. 常见问题

### 9.1 登录相关

**Q1: 忘记密码怎么办？**
A: 联系全局管理员重置。流程：管理员 → 用户管理 → 找到用户 → 编辑 → 重置密码。

**Q2: 登录后立即被踢出？**
A: 检查 Cookie 是否被浏览器禁用，或 Session 过期（默认 7 天）。

**Q3: 企微登录失败？**
A: 检查系统配置 → 企微 → CorpID、AgentID、Secret 是否正确，回调地址是否在企微后台配置。

### 9.2 需求相关

**Q4: 创建需求时看不到某个项目？**
A: 联系管理员将你加入该项目（项目访问权限）。

**Q5: 状态卡住无法推进？**
A: 检查当前处理人是否就是自己，或者是否需要退回上一步。

**Q6: 附件上传失败？**
A: 检查文件大小（默认 ≤ 100MB），或网络问题。

**Q7: 找不到某个需求？**
A: 检查项目过滤、状态过滤、或者需求已被删除（管理员可恢复）。

### 9.3 AI 集成

**Q8: AI 聊天不回复？**
A: 检查系统配置 → LLM → API Key 是否正确，余额是否充足。

**Q9: MCP Token 失效？**
A: 登录 → Token 管理 → 撤销旧 Token → 创建新 Token → 更新客户端配置。

**Q10: Claude Desktop 看不到 RMS 工具？**
A: 
1. 检查 `claude_desktop_config.json` 路径是否正确
2. 重启 Claude Desktop
3. 查看 Claude 日志（macOS: `~/Library/Logs/Claude/`）

### 9.4 性能问题

**Q11: 列表加载慢？**
A:
- 缩小筛选范围
- 减少每页条数
- 联系管理员查看 MySQL 慢查询日志

**Q12: 仪表盘数据不准？**
A: 数据有 1 小时缓存，刷新会重新计算。
