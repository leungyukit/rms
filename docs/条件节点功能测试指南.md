# 条件节点功能测试指南

## 📋 功能概述

条件节点是 RMS 工作流引擎的新增功能，允许您：
- 在流程节点中配置条件
- 根据需求状态、优先级、字段值等决定流程走向
- 支持多种条件类型

## 🎯 支持的条件类型

| 条件类型 | 说明 | 配置格式 |
|---------|------|---------|
| `status` | 需求状态 | 状态值（可多选，用 \| 分隔） |
| `priority` | 优先级 | 优先级值（可多选，用 \| 分隔） |
| `field_eq` | 字段等于 | 字段名:比较值 |
| `field_contains` | 字段包含 | 字段名:比较值 |
| `field_gt` | 字段大于 | 字段名:比较值（数字） |
| `field_lt` | 字段小于 | 字段名:比较值（数字） |
| `time_gt` | 处理时间超过 | 时间值（如：2h, 30m） |
| `time_diff_gt` | 创建时间差大于 | 天数（如：7） |
| `time_diff_lt` | 创建时间差小于 | 天数（如：7） |

## 🧪 测试步骤

### 步骤 1：访问流程设计界面

1. 打开浏览器
2. 访问：`http://localhost:3800/workflows/designer`
3. 登录系统（用户名：`admin`）

### 步骤 2：创建测试工作流

1. 点击"新建流程"或编辑现有流程
2. 拖拽节点到画布：
   - 1个开始节点
   - 1个条件节点
   - 2个任务节点（标记为"路径A"和"路径B"）
   - 1个结束节点
3. 连接节点：
   ```
   开始 → 条件节点 → [条件满足] → 路径A → 结束
                  ↓ [条件不满足]
                  路径B → 结束
   ```

### 步骤 3：配置条件节点

1. 点击条件节点
2. 在右侧属性面板中配置：

**测试用例 1：需求状态条件**
- 条件类型：选择"需求状态"
- 条件值：选择"处理中"（或输入：`in_progress`）
- 条件描述：输入"状态为处理中时走路径A"

**测试用例 2：优先级条件**
- 条件类型：选择"优先级"
- 条件值：选择"高"和"中"（或输入：`high|medium`）
- 条件描述：输入"高/中优先级走路径A"

**测试用例 3：时间条件**
- 条件类型：选择"处理时间超过"
- 条件值：输入"2h"（2小时）
- 条件描述：输入"处理超过2小时走路径A"

### 步骤 4：保存工作流

1. 点击"保存流程"
2. 输入流程名称：`测试条件节点`
3. 保存

### 步骤 5：创建测试需求

1. 访问需求列表页面
2. 创建一个新需求
3. 设置状态为"处理中"
4. 设置优先级为"高"
5. 保存

### 步骤 6：启动工作流实例

1. 在需求详情页，点击"启动工作流"
2. 选择刚才创建的测试流程
3. 启动流程

### 步骤 7：观察流程走向

1. 检查当前节点是否正确
2. 如果需求状态是"处理中"，应该走路径A
3. 如果需求状态不是"处理中"，应该走路径B

## 🔍 调试信息

如果需要调试，可以查看：

1. **工作流实例日志**：
   ```sql
   SELECT * FROM instance_logs WHERE instance_id = [实例ID] ORDER BY created_at DESC;
   ```

2. **实例节点状态**：
   ```sql
   SELECT * FROM instance_nodes WHERE instance_id = [实例ID];
   ```

3. **条件节点配置**：
   ```sql
   SELECT node_key, type, config FROM instance_nodes 
   WHERE instance_id = [实例ID] AND type = 'condition';
   ```

## ⚠️ 注意事项

1. **向后兼容**：现有工作流不受影响
2. **配置格式**：条件配置存储为 JSON 格式在 `config` 字段中
3. **边的顺序**：条件节点的出边顺序很重要 - 第一条是条件满足的路径
4. **等待机制**：如果没有匹配的边，流程会等待条件满足
